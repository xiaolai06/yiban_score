# 学绩 · 学生成绩管理 V2

支持本机运行和 Ubuntu 云服务器部署的学生名单、学院班级层级、考试状态与得分率管理网站。在 V1 完整项目上升级，前端、后端、数据库迁移、自动化测试均包含在本包内。

**源码包不含真实名单、真实成绩或预装数据库。** `data/` 初始仅有 `.gitkeep`。两个填写模板使用虚构学生。真实学生信息只应通过私人渠道备份和迁移，不要随代码公开。

云服务器部署请直接阅读 [部署指南](deploy/README.md)。云端使用已确认空闲的 `sz-yiban.duckdns.org`、Nginx HTTPS 和访问 IP 白名单；应用没有账号登录。后端仍只监听服务器内部的 `127.0.0.1:8000`。

## 1. 先启动，再导入

### Windows

1. 安装 Python 3.11 或更新版本，建议 3.11–3.13，勾选添加到 PATH。
2. 完整解压 ZIP。不要在压缩文件预览窗口里直接运行。
3. 双击 `start_windows.bat`。首次会创建 `.venv` 并联网安装 `requirements.txt`。
4. 保持终端窗口运行，在浏览器打开 `http://127.0.0.1:8000`。
5. 首次使用：先到“名单导入”上传学生名单，再到“导入成绩”上传考试报表。
6. 停止服务：在终端按 `Ctrl+C`。

不需要 Node.js、npm、外部数据库或 Office。运行时处理数据不调用云端服务；首次安装 Python 包需要网络。本次实测环境是 Linux / Python 3.13，未在实体 Windows 电脑上执行双击安装验收。

命令行手动启动：

```bat
cd /d D:\你的项目目录\student-score-site
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

PowerShell 中，最后两行可使用 `& .\.venv\Scripts\python.exe ...`。也可以直接双击批处理文件。

### Ubuntu / Linux

```bash
cd student-score-site
bash start.sh
```

需要系统已安装 Python 3.11+ 及其 `venv` 支持。手动方式：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

端口被占用时：`python run.py --port 8001`。云端默认使用 8000，部署前确认该端口空闲。可指定数据库：`python run.py --db /absolute/path/students.sqlite3`。不要把数据库参数指向他人的数据库或正在被其他程序修改的文件。

## 2. 从 V1 升级：保留你电脑里的原数据

**推荐解压到新文件夹，不直接覆盖正在运行的项目。**

1. 先在旧网站下载 SQLite 备份；然后在旧终端按 `Ctrl+C`，确保旧服务停止。
2. 将旧项目的 `data/students.sqlite3` 复制到新项目的同名位置。如果你使用自定义 `--db`，复制那个实际数据库。
3. 启动新项目。系统检测到 V1 后，先自动创建备份，再将状态约束和成绩审计表升级到 V2。
4. 打开“成绩明细”核对人数，然后进入“导入成绩”。

自动迁移备份保存在原数据库旁的 `backups/` 中；默认路径类似：

```text
data/backups/students-before-v2-时间戳.sqlite3
```

迁移保留学号、学生资料、学院班级关系、已有状态/得分率、版本号和原名单导入日志。它不会主动把旧成绩改为新成绩；成绩更新仍需你在导入页面确认。迁移出现异常会回滚。V1 备份用于回退到旧程序，V1 程序不应继续操作已升级的 V2 数据库。

**SQLite 使用 WAL。不要在服务运行时仅复制主 `.sqlite3` 文件，否则可能漏掉尚在 WAL 的修改。** 优先使用网站备份功能，或正常停止服务后复制。也不要直接覆盖正在运行的数据库。

## 3. 使用已有数据库

本地和云服务器都支持使用已有 SQLite 数据库。请先从原网站下载一致性备份，并在目标服务停止后导入。云端数据库放在 `/var/lib/student-score/students.sqlite3`，具体命令见 [部署指南](deploy/README.md)。真实数据库、原始成绩文件和备份不放入公开 GitHub 仓库。

## 4. 页面和操作

| 页面 | 内容 |
|---|---|
| 名单导入 | 导入或剔除 XLS / XLSX 名单；普通导入按学号建立层级，剔除固定按 A 列学号预览确认后删除人员及成绩 |
| 导入成绩 | CSV / TSV / XLS / XLSX；编码识别、字段提取、清洗策略、逐行匹配、预览、异常确认、批次记录与撤销 |
| 成绩明细 | 学院/班级目录与当前成绩双栏；搜索、状态/空值/不合格筛选、目录及班级表头排序、学生勾选与整范围导出、成绩编辑、自适应分页及跳页；分类待跟进清单与全量导出 |
| 数据总览 | 学生/学院/班级总数、已完成人数（有正式成绩，含0分）、可排序的学院数据与状态分布 |
| 使用说明 | 核心规则、流程、统计口径和访问范围 |

数据总览直接显示四项汇总数据，不再显示重复页头、刷新/备份按钮及平均值说明卡。下方保留学院数据和考试/登记状态；学院名称、班级数、学生人数、已完成人数、合格人数均可点击表头切换升降序，默认按学生人数降序，同值按学院 ID 稳定排列。点击学院进入对应成绩明细，返回总览保留本次排序。顶部原“合格人数”卡片改为“已完成人数”，学院表原“已录入人数”也改为“已完成人数”：统计0–100有效正式成绩，包含0分和不及格成绩，排除空值及未开始/进行中的暂存分值；与已结算得分人数口径一致。学院表保留独立“合格人数”，按有效得分率≥60计算，恰好60分计入；状态分布仍展示原始登记状态，不改写学生记录。合格口径与成绩明细及Excel一致，考试进度单独跟进；已结算成绩及平均值仍排除未完成暂存分值。总览正文和表格字号适度加大、颜色加深；窄屏宽表在自身区域横向滚动，不压缩文字。备份仍可在使用说明页下载。

学院名称只保留原名称文字，不添加01等编号、背景外壳或箭头；点击查看成绩的功能保留。外层圆角、边框颜色、表头分隔和横向滚动条与成绩明细协调，取消学生人数下方的装饰条。若当前运行的旧后端缺少已完成人数或仍按90分合格，页面会只读分页读取全部有分数的记录，按新口径补算全校及学院的已完成、合格数量，并核对数据库revision和每学院录入人数；读取期间发生修改会重试一次，不会以0代替未知数量。读取失败时明确提示并支持重新读取。不需为了总览数量显示强制终止旧服务，Ctrl+F5即可加载新版前端；其他新增后端功能仍需正常重启服务。

成绩明细仅保留两个工作区：左侧学院/班级目录，右侧当前浏览范围的成绩。桌面两栏等高，距离视口顶部/底部的留白一致，右侧根据视口定高；默认按表格可用高度自动计算每页条数，窗口变大时显示更多记录，也可手动选择条数、翻页和跳转页码。窄屏上下排列。页头仅显示全校/学院/班级及其总人数；合格人数（有效数值得分率≥60）、不合格人数（<60或无有效数值）、已结算得分人数和平均得分率随搜索/筛选更新。全站与Excel统一以60分及以上合格；不因未开始/进行中/缺考等状态排除≥60分。考试进度通过待跟进清单单独查看。此分类不修改原状态/分数，不把空值变为0；已结算人数和平均值继续排除空值及未开始/进行中，真实完成0分仍参与平均。暂存数值在明细原样显示，并通过状态和提示区分未结算。

总人数加大显示，移除搜索行的重置按钮；得分率下拉提供“不合格（含无成绩）”，与不合格人数及导出使用同一规则。左侧名称/人数按钮同时排序学院和下属班级；右侧只显示班级，并支持点击班级表头排序，选择班级后的标题也只显示班级名称。

已结算得分人数和平均值仅使用0–100的真实数值成绩，排除空值、横线、占位文本和未开始/进行中记录；真实完成0分计入。统计覆盖当前筛选的全部记录，不只统计当前页。刷新、筛选及翻页保留列表结构，更新期间显示上次结果和更新提示，失败时可重试；重复请求与过期响应不会覆盖新筛选。异常人员弹窗同样保留列表、滚动位置与搜索输入，姓名完整换行显示。

目录范围勾选与学生勾选彼此独立。全校勾选框仅在明确点击全校全选时打勾，勾选学院/班级不再自动把全校标为选中；学院的部分选中以浅色横杠表示。成绩表每行可勾选学生，表头全选覆盖当前筛选范围的全部学生（不限当前页），之后可取消个别人；翻页/排序保留勾选，变更搜索/学院/班级/状态/得分筛选会清除学生勾选，避免误导出其他范围。

导出菜单分别提供“勾选学生”“勾选学院/班级（无勾选时为当前范围）”“不合格”。整学院/班级导出包含完整范围，不受当前页或搜索截断；指定学生仅导出其本人，表头全选按筛选快照与取消名单导出。无任何勾选时，当前范围导出仍可用，不合格导出按当前筛选；有学生勾选时优先导出这些学生中的不合格成绩，否则使用目录勾选。不合格导出仅包含低于60分或无有效数值得分率的人员，任何状态的空值均不遗漏；未开始/进行中但已有≥60数值的人员另列进度跟进，不混入低分不合格；仅无成绩的班级也会生成工作表。结果为 XLSX，每个实际班级一个工作表，保留文本学号、原状态、得分率和百分制得分；空值不改成零。所有下拉、勾选和选中态使用本地自建样式。

**新版 Excel 导出样式与说明表：** 班级明细、数字及空成绩单元格统一水平/垂直居中；中文采用微软雅黑（Microsoft YaHei），数字采用 Times New Roman（新罗马），文本学号和班级名称中的数字也使用数字字体。学号仍为文本，保留前导零；原状态、真实0分和空值不变。字体不嵌入文件，查看设备未安装时由 Excel/WPS 替代。异常人员 Excel 也统一字体及居中样式，但不将异常备案混入正式人数统计。CSV 仍是纯文本，不能设置字体/对齐或多工作表。

学生成绩 Excel **最后增加「导出说明」工作表**，显示本次实际导出总计及各班级的导出人数、参与人数、未参与人数、参与率、合格人数、合格率和合格占导出人数比例，并写清公式：

- 参与人数：有效数值得分率 **>0**；空值、0及其他无有效数值得分率不算参与，真实0仍原样保留在明细。
- 参与率＝参与人数÷导出人数。
- 合格人数：有效得分率 **≥60**，恰好60计入；本说明仅按得分率，不按未开始/进行中等状态排除。
- 合格率（占参与人数）＝合格人数÷参与人数；没有参与人员时显示“—”，不伪造0%合格率。
- 合格占导出人数比例＝合格人数÷导出人数，作为不同分母的补充指标。

只统计文件里实际输出的学生，不扩大全校，也不只取页面当前页。勾选、取消个别人员、学院/班级并集和不合格筛选均按最终导出快照计算；总计按人数汇总后求比例，不平均各班级比例。比例显示两位小数。**全站合格人数、不合格筛选及本说明统一按有效数值得分率≥60判断，恰好60计入合格**；未完成高分仍在进度跟进清单，但不再作为低分不合格导出。已结算成绩及平均值保持原结算规则，参与率仍按>0、不含0及空值计算，不等同于实际缺考判断。

导出菜单同步显示说明；选择导出后关闭菜单，方便连续导出。新版响应带 `X-Export-Workbook-Version: 6`，缺少该能力时前端会要求重启，不静默下载缺少说明表的旧文件。请在启动窗口Ctrl+C停止后重新启动 `start_windows.bat`，浏览器Ctrl+F5。无需迁移数据库或安装新运行依赖；导出不会写数据库。当前验收见 [60分全站适配报告](docs/PASS_SCORE_60.md)，旧[导出样式测试报告](docs/EXPORT_FORMAT_TEST_REPORT.md)仅作历史记录。

若启动窗口仍运行旧后端，成绩明细会只读分页读取完整录入成绩，按统一≥60规则补算统计，并核对revision，修改期间重试一次；补算失败显示未知值和错误，不伪造0或继续展示旧合格口径。新页面和请求统一使用`below_60`（不合格）和`at_60`（恰好60，合格子集），不从总人数重复扣除。仅服务器保留旧`below_90`筛选/导出开关/计数字段为相同不合格规则的别名；旧`at_90`学生计数仍只指真实90分，不冒充60分。新版不合格导出/筛选要求 directory_api_version≥6、Excel格式版本≥6；旧版本字段或口径不同，须重启，不能静默下载旧名单。新版后端按完整筛选快照返回统计，不从当前页猜算。

“得分率”保留百分比；原“成绩来源”列改为百分制“得分”：86% 显示为 86 分，86.75% 显示为 86.75 分，空值显示为“—”，真实 0 显示为 0 分。这只是显示换算，不更改数据库或导入记录。“学生档案”独立页面及入口已移除；原学生数据、学院班级关系和成绩编辑接口保留，旧 `#students` 书签转到 `#scores`。成绩明细不再显示独立顶部导出/导入区、全校说明条和底部统计口径说明；导出整合进搜索行，成绩导入及审计导出仍在独立导入页面提供。

整个界面重新统一了深色文字、浅色背景、清晰边框、较大的字号与控件。正文 16px，主标题 32px，常用表格 14px，主要控件最小高度 44px。桌面侧栏固定；小屏重新排布，宽表格在自身容器中滚动。

### 辅导员待跟进清单

入口在 **成绩明细右上角「待跟进」**，按当前全校/学院/班级范围读取，独立于成绩页状态/得分率下拉。支持独立搜索、分页、刷新、Excel/CSV导出当前分类的全部页。清单只读，不修改原分数、进度、姓名或班级。

- **未录入成绩**：空值或无有效数值得分率，任何状态均可出现。
- **未开始 / 进行中**：按原考试状态分别列出；已有≥60分也需要跟进进度，但分数已经合格。
- **已完成低于60**：已完成/已录入且有0≤分值<60的学生，真实0也包含。
- **其他低分需核对**：其余状态的有效低于60分，避免遗漏缺考/免考等需要人工判断的记录。
- **恰好60（已合格）**：按新及格线核对，不能称为不合格；不因这一分类单独计入待跟进总数。旧“恰好90”分类及下载文件名已移除，60–89.99分全部正常合格。
- **历史异常核对**：复用已保存成绩导入异常，显示姓名冲突、名单外学号、数据错误等及原原因，明确区分当前成绩和历史分值。历史出现不等于“仍未解决”，不计入正式在册或待跟进人数；学院/班级只显示可按学号绑定当前名单的异常，未知归属只能在全校查看，不猜测班级。

待跟进总人数按当前在册人员去重，分类可能交叉，不能把分类人数直接相加。已剔除学号不再出现。导出包含分类及原因，不只导出页面20行；导出时核对读取清单的revision，其他窗口修改后须刷新再导出。没有数据时不生成假记录；接口不可用时明确要求重启，不把读取失败当成0人。

本轮只实现统计口径统一和分类核对清单，不包含联系时间/催办备注/处理状态编辑，也不伪造异常已经解决。加载需重启后端再Ctrl+F5；跟进接口版本为4；当前验收见 [60分全站适配报告](docs/PASS_SCORE_60.md)，[旧跟进测试报告](docs/FOLLOW_UP_TEST_REPORT.md)仅作历史记录。

### 剔除不需要的人员

新增入口在 **名单导入 → 剔除名单**，不新增独立侧栏模块：

1. 在原启动窗口按 `Ctrl+C` 停止旧服务，再启动 `start_windows.bat`；浏览器按 `Ctrl+F5`。旧服务不支持时页面会阻止操作，不用普通导入冒充剔除。
2. 选择需要剔除的 XLS / XLSX，例如你提供的 `学生名单列表 (29).xls` 这种「学号、姓名、院系、班级」格式。**固定以 A 列学号为唯一绑定依据**，表头须为“学号”；其他列不决定删除对象。支持选择工作表和表头行。
3. 点击“生成剔除预览”。查看将删除人数、未匹配学号、重复行和错误行；下载完整 CSV 核对表检查全部学号。页面只展示前25个，不代表只处理25人。重复学号去重，空行和重复表头跳过，其他非法学号阻止整批删除。数字学号不猜测丢失的前导零或精度。
4. 如需恢复保障，先点击“删除前下载数据库备份”。核对全部学号，勾选永久删除确认，输入 **确认剔除** 后提交。

确认后通过一个 SQLite 事务删除匹配学生的基础资料、当前成绩、`student_changes` 修改审计、`score_import_rows` 历次明细（包括可绑定学号的异常记录）。只清理本次剔除导致空出的班级/学院，不动其他学生或原有空目录。所有正式名单、统计、筛选和导出均不再包含被剔除人员。

数据库只留下最小的剔除学号标记及批次汇总，不额外保存被删姓名或成绩快照。**已剔除学号（包括本次未匹配者）后续普通名单导入自动跳过，重启后仍生效**；不会按姓名推测或删除其他人。成绩导入不创建名单外学生，因此也不会让其重回正式统计；之后主动上传新的成绩文件仍遵循既有异常归档规则。涉及已清理明细的历史成绩批次禁止整批撤销，其余人员的成绩不受影响。旧成绩/名单批次的原始汇总仍保留，它们是历史操作结果，不是当前在册人数。

剔除记录完整分页保存。预览后数据库改变会拒绝提交，需重新预览；同一确认令牌重复提交幂等，不会误删其他人员。无在线撤销或解除剔除按钮；需要恢复时须停服恢复删除前备份，并核对备份后的其他变动。不要退回不支持剔除标记的旧后端继续导入。

原始 Excel、之前的下载和备份不会被改动或删除。成功剔除后清理本次临时上传和过时预览；磁盘文件被占用时临时清理为尽力执行，保留既有过期清理机制。SQL 删除不承诺磁盘级安全擦除，备份与源文件仍须妥善保管。开发验收仅用临时数据库，未替用户确认删除真实人员。验收见 [剔除名单测试报告](docs/ROSTER_REMOVAL_TEST_REPORT.md)。

本仓库包含使用虚构样例运行的自动化检查。实际学生名单与成绩核对材料单独保存，不作为公开源码发布。

## 6. 数据清洗规则

### 6.1 只按学号，不按姓名猜测

`学号` 是唯一键，TEXT 保存，保留前导零及不同长度。姓名相同不合并。缺姓名但有有效学号时，查询名单；非空姓名与名单冲突则列为异常。

| 原值（虚构示例） | 清洗结果 |
|---|---|
| `` `0000000001 `` | `0000000001` |
| `'0000000001` | `0000000001` |
| `０００００００００１` | `0000000001` |
| `0000000001.0` | `0000000001` |
| 前后空格 / 零宽字符 | 去掉格式字符 |
| 文本 `="0000000001"` | 只解析这种纯数字文字包装；不执行表达式 |
| 科学计数法 / 丢失精度的长数字 / Excel 公式 | 拒绝猜测，列异常 |

清洗不会任意提取字符串中间的数字。源表早已丢失的前导零无法可靠恢复；请重新从平台导出文本学号，不手动补猜。数值型超过 15 位的学号单元格拒绝导入，避免拿已经丢失精度的值去匹配。

### 6.2 只提取需要的字段

自动识别并可手动修改映射：学号、姓名、状态、得分率、成绩/百分比、开始时间和结束时间，以及用于核对的学院和班级。时间为可选字段，按表头识别而非盲目固定列号；标准考试报表为 L 列开始、M 列结束。用户名、易班 ID、昵称、系统评定时间等其他列不写入学生表。

优先使用 `得分率`。例如 `成绩 / 百分比` 中的 `75 / 62.5%` 只提取右侧明确的 `62.5%`，**不是做 75÷62.5，也不在满分未知时推断百分比**。两列都有数值时交叉核对；不一致则列为异常，不能悄悄挑一个。

默认单位是 0–100：`92` / `92.0%` / `９２％` → `92%`。普通 `0.85` 代表 `0.85%`，不会自动放大。若你确知平台用 0–1 小数比例，请在页面显式选择比例模式，此时 `0.85` → `85%`。有百分比单元格格式的 Excel 数值按其格式读取。统一限制 0–100，保存到两位小数；非法、无穷、NaN、公式不作为成绩。

### 6.3 状态与 0 分

支持：待录入、未开始、进行中、已完成、已录入、缺考、免考。保留报表中“已完成 / 进行中 / 未开始”的业务含义，不全部改成“已录入”。

默认策略：

- 未开始 / 进行中 + 0 → 得分率 `NULL`，显示“未结算”。原始 0 分保留在批次审计中。
- 已完成 / 已录入 + 0 → 真实 `0%`，参与有效平均。
- 已完成 / 已录入但两处得分率都缺失 → 异常，避免把没有成绩的数据当成完成。
- 缺考或免考不自动凭空填 0 分。

**“未完成的 0 属于占位值”是本项目的默认业务规则，而不是对任何考试平台都无条件成立的事实。** 页面可改为保留未完成的 0。无论是否保留，状态为未开始/进行中的分值都不参与平均统计；其他非空得分率参与，空值不参与。

### 6.4 重复、冲突与错误

同一文件中，同一学号的有效重复记录按较高得分率合并，只写入一次；默认优先使用已完成的记录，分数相同时可补充更完整的状态。每条原始行仍保留在审计中。如果其中任何一行存在非法数据或姓名冲突，或并列记录的缺考 / 免考等状态无法确定，整组列为异常，不从错误记录中任意挑选。CSV 列数错位、未知状态、越界分数、未知学号、姓名冲突均有明确原因。

遇到异常，默认不能提交。必须修正文件重新预览，或勾选“跳过异常，仅导入可匹配记录”。跳过的记录仍留在批次审计，不会静默消失。如果整份文件只有异常数据，也可明确勾选“仅保存异常记录，不修改正式成绩”后确认保存；不创建缺少身份的学生，也不把异常分数写入正式成绩。

### 6.5 答题时长（结束时间－开始时间）

- **时间始终选填。** 旧报表没有开始/结束列、单元格为空或旧记录未保存时间时，成绩仍可正常导入、查看、导出；页面显示“—”、新版导出时间留空，不必补列，也不必重新导入已有成绩才能使用。
- 导入时自动计算 **M 列－L 列**，例如 `11:15:08－11:02:15` 显示 `00:12:53`。统一为 **时:分:秒**，跨天正常相减，超过24小时不归零；原时间含小数秒时，时长不足1秒部分舍去。
- 支持带完整日期的常规时间文本和有明确日期格式的 Excel 日期单元格（识别1900/1904日期系统）；不猜测纯数字、仅时分秒或时间戳。不使用“系统评定时间”或当前时刻代替结束时间。
- 时间缺失、仅有一端或结束列为 **未正常交卷** 时，时长留空，页面显示“—”；真实0秒显示 `00:00:00`，两者不同。“未正常交卷”原标记在审计中保留，不因此改写成绩/状态。非法日期、公式、时区不一致或结束早于开始列为异常，需核对或明确跳过。
- 成绩明细新增“答题时长”列，悬停显示开始/结束时间，编辑框内可只读查看；导入预览/历史批次、待跟进及异常人员表格也展示对应时长，名单导入/剔除核对预览同步展示在库时长。CSV、分班Excel、勾选学生/范围/不合格及异常导出均带对应时间/时长。**数据总览及其人数统计不添加时长。**
- 仅想补齐旧记录的时长时，才需要在新版服务上传包含时间的报表、核对映射并确认导入：**相同得分率、相同状态且缺时长**可补齐，不需要提高分数；已有完整时间的同分记录默认保留原来源。较低成绩受保护时连同高分时间一起保留；新高分没有时间时不沿用旧低分时长。不同同分尝试的时间冲突需人工核对。
- 开始/结束及秒数与成绩一起持久保存，批次撤销一并恢复；名单更新不清空，手工修正状态/分数不改导入时间。启动时自动给旧数据库添加可空字段，原记录不改分、不伪造时间，旧批次保持历史快照。建议更新前备份，勿与旧版程序同时操作数据库。

前端也兼容仅缺少时间功能的旧服务：原成绩导入继续可用，分班Excel v5 / 待跟进v3照常导出原格式并普通提示“不含答题时间”，不因缺时长拦截；未核实及格规则、更严重数据错误或真正请求失败仍保留原保护。CSV只缺末尾可选时间值可正常读取，“暂无/未填写/未提供”等占位时间也不报日期错误。

完整规则及本次669项测试验收见 [答题时长功能与验收](docs/ANSWER_DURATION.md)。

## 7. 导入覆盖、回退与审计

默认采用 **增量导入、保留较高得分率**（`keep_highest`）：已有名单中未录入的成绩补入；本次得分率更高时更新，较低或空值时保留原成绩；相同分数不重复覆盖或改变来源。相同分数时可补充更完整的登记状态，例如进行中变为已完成；同分同状态也可补齐缺失的答题时间。真实 0% 与未录入不同。已完成记录仍受到保护，不被新的未开始 / 进行中记录降级。预览与导出均显示“导入前 → 合并后”的得分率。

页面不再提供直接覆盖 / 关闭保护的选项；API 为既有集成保留显式 `replace` / `fill_missing` 参数，未指定模式的请求均使用 `keep_highest`。已有历史批次继续按原规则快照展示，不重新计算或删除。

名单导入与成绩导入职责分开：重复导入名单保留已有状态/得分率；成绩导入不修改学生姓名或学院班级。成绩表没有出现的学生也不会被删掉或清空。

每次确认成绩导入均产生批次，**包括全部保留、没有成绩更新的导入**。保存文件摘要、规则、统计、选定字段的原始值 / 清洗值、每行处理结果、修改前快照和版本；跳过的异常行和合并的重复行也保留。全部批次与明细长期保存，页面每页显示 10 批，分页不代表只保留最近 10 批，也没有 50 批总量上限；重启和撤销不会删除历史。重复点击同一个确认请求是幂等的，不产生重复批次。再次上传同一文件会保存新的导入记录；相同或较低得分率不重复改成绩。

“导入成绩”顶部的 **异常人员** 打开历次已保存导入的汇总弹窗，支持搜索、分类、分页、查看每次出现及 **Excel / CSV** 导出。按有效学号增量合并，保留最高可识别的 0–100% 得分率；分数相同时保留原最高分来源，同时继续累计出现记录与批次数。姓名冲突时保留原表 / 名单的各个姓名，不猜测身份；无效或缺失学号的行单独保留，避免按同名合并。非法分数不参与最高值比较，但原始值始终可追溯。

异常汇总直接读取已有持久批次，不依赖浏览器缓存，不需要重新导入旧文件；后续修正成绩或撤销批次不会自动删除历史异常。导出包含当前筛选的全部汇总或全部出现明细，不限当前页；也可单独导出一个汇总项的全部出现记录。异常人员只是历史备案，不会自动加入学生名单或参与正式成绩统计。

预览使用数据库修订号。预览后其他标签页修改了学生或新增导入，旧预览不能直接覆盖，必须重新生成。提交/撤销均使用单一 SQLite 事务，失败整体回滚。

在“导入成绩→历史记录”可查看/导出批次，也可确认撤销。只有该批更新的每名学生仍是导入后的版本且来源未被改动时才能撤销；任意一人被后续编辑，整批撤销拒绝执行。此规则是保守保护，**不是可以任意顺序撤销的时间机器**。手动编辑会清掉“当前来源批次”，但历史审计仍保留。

## 8. 存储、导出与隐私

本机模式的业务数据默认保存在 `data/students.sqlite3`；云服务器模板使用 `/var/lib/student-score/students.sqlite3`。也可用 `--db` 指定位置。数据不存于浏览器 localStorage，刷新页面或正常重启不会清空。

导出 CSV 使用 UTF-8 BOM；异常导出带行号、原/清洗后学号、原始及清洗状态/得分率、名单资料和原因。CSV 无法强制 Excel 单元格格式；用 Excel 查看学号时，应通过“从文本/CSV”导入并将学号列设为文本，避免 Excel 自行去掉前导零。公式开头的文字做导出转义，避免被当作公式执行。

数据库所在目录的 `.staging/` 是临时上传/预览文件。预览有效期 60 分钟；成功提交成绩后清除该上传及关联预览。未提交的临时文件由启动或后续上传触发过期清理，**不是后台计时器到点立即删除**。正式批次审计会长期留在数据库，备份、导出都可能包含学生资料，需按真实业务资料保管。

默认本机模式仅允许回环地址访问；云端模式只接受配置域名的 HTTPS 请求，由 Nginx 使用公网 IP 白名单限制访问。应用没有账号登录或角色权限，云端部署必须保留白名单；仅修改监听地址不能安全发布。

## 9. 本版的数据模型边界

**每个学生当前只有一份状态与得分率。** 批次名称用于追溯导入来源，不等于独立考试、科目或学期实体。如果先导入考试 A 再导入考试 B，默认会保留两者较高的有效得分率；各次导入的历史快照仍在审计中，但没有多考试并排成绩单。

本版尚未包含：多科目/多场考试独立管理、满分与实得分计算、排名、账号角色、多用户协作。这些属于后续业务扩展，不能将现有批次记录误称为已经完成的多考试系统。
