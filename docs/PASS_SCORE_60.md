# 60分全站适配与验收（2026-10-20）

## 现行规则

- 有效数值成绩为0–100；**60分及以上合格，恰好60计入**，60–89.99分不再归为不合格。
- 不合格为低于60或无有效数值；无成绩不会自动写成0。考试进度仍独立跟进，不因未开始/进行中状态把≥60分成绩称为低分不合格。
- 总览顶部原“合格人数”、学院表原“已录入人数”改为“已完成人数”：有正式数值成绩且非未开始/进行中，包含真实0分及不及格成绩。学院表仍保留独立的60分合格人数。
- 不改写原始学生状态、分数、学号或既有导入审计，不把真实90分改为60分。

## 全站适配范围

| 位置 | 适配 |
|---|---|
| 数据总览 | 全校和学院已完成/合格统计，排序、失败提示及旧服务分页补算 |
| 成绩明细 | 合格、不合格、完整筛选快照，搜索、学院/班级范围与分页 |
| 不合格筛选及下载 | 新页面统一使用`below_60`，仅导出最终选中范围内的不合格人员 |
| 普通分班Excel | 本次总计、每班合格人数、合格率、表头及末尾说明全部按60分计算 |
| CSV | 全部筛选数据与Excel、页面人数一致，保留空值和真实0 |
| 待跟进 | 已完成低于60、其他低分、恰好60（已合格）；去重及进度单独统计 |
| 跟进Excel/CSV | 分类、原因、资格文字及下载文件名均按新60分边界；移除旧恰好90分类 |
| 使用说明和接口文档 | 显式解释60分及格、完成不等于及格、0分和空值不同；旧报告标为历史 |

后端`server/grade_rules.py`与前端`web/grade_values.js`均定义`PASS_SCORE=60`，统计SQL、Python导出和前端只读补算使用共享判定。成绩导入的最高分合并、保护已有成绩、批次撤销与来源归属规则不变。

## 接口与兼容

- 当前工作区健康能力：`directory_api_version=6`、`score_export_workbook_version=6`、`follow_up_api_version=4`；后两者已包含同时存在的答题时间/时长适配。
- `/api/stats`和`/api/students`提供`pass_score=60`；学生统计增加`below_60`、`at_60`、`completed`。
- 新前端的筛选、请求、统计节点和导出开关均使用60命名。旧`below_90`仅留在服务器作为相同不合格规则的兼容别名；两个导出开关任一为true即筛选不合格，不扩大范围。
- 旧学生统计`at_90`仍表示真实90分人数，不改义为60；新界面不用它判断资格。旧跟进`kind=at_90`已移除，非法旧分类返回422，刷新客户端后使用`at_60`。
- 旧服务无法提供新筛选/下载时明确提示重启；总览、明细可在完整分页及revision校验后只读补算，失败显示未知而不是伪造0。
- 既有答题时长功能保留，本轮没有回滚其他工作区的相关修改。详情见`DATABASE_AND_API.md`的时间字段章节。

## 启用

1. 在原服务窗口正常按`Ctrl+C`停止服务。
2. 在项目目录重新运行`start_windows.bat`。
3. 浏览器按`Ctrl+F5`刷新；若已有旧报表，需要重新导出。

本轮测试使用临时数据库和合成学生数据；验收阶段未向真实学生库提交写入、未安装依赖、未重启/部署用户服务。Git发布另按用户授权执行，以仓库提交记录为准。实际启用同时包含的其他功能时，以该功能自己的迁移说明为准；60分判定本身不要求改写现有成绩。
