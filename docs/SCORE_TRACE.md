# 异常原始行与人员状态查询

更新：2026-10-27。本轮修改包含源码、测试与说明文档；没有自动导入真实报表、修改真实学生库或重启生产服务。GitHub 发布按用户授权执行，真实数据库、备份、原始报表及测试缓存不随源码提交。

## 入口与使用

1. **导入成绩 → 异常人员**：显示清洗后学号、数字文本易班 ID、原 ID、各姓名/归属、最高记录及来源、次数、异常原因。可搜索学号、原始/清洗后易班 ID、姓名、学院班级、异常原因、批次名、文件名；支持输入后自动检索、回车/查询按钮立即检索、清空、分类和分页。
2. **出现记录 → 展开原始行**：在列表下方展开全宽区域，显示准确的批次、文件、工作表、原表逻辑行号、导入时原值/清洗值、时间、原因及全部原始列。切换到另一行时不混用前一批的数据；刷新保留已展开内容，读取失败可重试。
3. **成绩导入记录 → 明细 → 展开原始行**：同样查看该行历史快照，不把现在的学生成绩误当成导入时的值。
4. **顶部“异常人员”旁 → 人员状态查询**：按学号、姓名、历史易班 ID、学院班级/专业及当前状态检索正式名单；显示当前姓名、归属、状态及解释、得分率、时长、成绩来源和更新时间。可带学号往返历史异常，查询不到时也可跳到异常检索。
5. **状态与处理结果说明**：七种登记状态、占位0、合格/结算、四类异常及批次处理/撤销含义可展开阅读。

## 数据边界

- 学号仍是唯一身份匹配键；易班 ID 只供历史检索，不替代学号、不向 students 写入账号、不按同名/账号同号合并人员。一个账号涉及多个学号时分别显示。
- 易班 ID 保存为文本，清除明确前缀、全角、隐藏空白和 `.0` 尾缀，保留前导零；不猜测科学计数法、不恢复数字单元格已丢失的精度、不从任意字符中抽取数字。非法可选账号只保留原值/说明，不阻止其他有效成绩。
- 人员状态查询读取当前本地正式名单和最后保存成绩，**不联网查询易班平台实时状态**，不提供联系/催办/异常已解决的虚假标记。
- 已完成 ≠ 合格；无有效成绩 ≠ 缺考；免考不自动补满分。有效数值 ≥60（含60）合格，状态与分值独立；未开始/进行中的分数不计已完成和平均值，真实完成0分仍计结算。
- 异常最高分、出现记录和正式成绩分别展示。后续修正或批次撤销不删除历史异常，也不说明历史异常目前仍未解决。

## 整行快照与旧记录

从新版生成的导入预览确认保存后，`score_import_rows.record_json` 会同时保留 `source_row`：工作表、表头/原表逻辑行号、源列序号及表头、原始读取值、格式化读取值、Excel 数字格式和公式/错误标记。CSV 同名单列、空表头/空列、尾部空列及单元格换行不折叠；字段内换行不改变逻辑记录号。

这些是**导入读取时的单元格数据**，不是原始工作簿文件：不重建 Excel 排版、宏、图像或公式表达式，不执行公式，只保留读取到的缓存值与公式标记。成功保存后原始临时文件仍按原机制清理。

**旧批次此前没有保存过全部列或易班 ID，不能凭空恢复。** 旧记录继续显示原有真实字段，并明确提示缺少完整快照；不回填猜测、不清空既有成绩。需要完整列时，重新上传原文件、核对并确认，会新增一次导入记录，按原“保留较高分”规则合并，不改写旧批次历史。旧版本生成的未过期预览也仍按其实际保留字段处理。

整行快照仅保存在本地审计数据库，不另设云端上传或第三方头像/查询服务。未映射的额外列现在也可能包含个人资料，请不要导入无关敏感列，并妥善保管数据库/备份；整行快照会增加存储体积。名单剔除仍按精确学号连同历史行一起清理，旧备份/源报表不自动擦除。

## 兼容和布局

- schema_version 仍为2，不新增业务表、不重写历史数据；health 增加 `score_trace_api_version=1` 和 `score_people_api_version=1`。
- 前端依据 analyze.fields 判断可选易班 ID 能力。旧服务不发送未知映射字段，继续原成绩导入；缺少新查询/原始行接口时显示该组件内的提示，不导致全页不可用。
- 缺少新 JSON 键的旧汇总/旧明细可继续打开和导出；导出追加易班 ID 等列，不移动原有列，不把大 JSON 强塞进 Excel 单元格。
- 保留原页面壳、圆角、配色、自定义下拉和表格。展开区在表格下方占满可用宽度，打开时回到弹窗内容左侧，不在末列挤压或藏在横向滚动之外。
- 桌面人员查询使用表格，小屏改为按人纵向卡片。320–1920px 六种宽度及横屏/低高度覆盖；长数据在组件内滚动，关闭后恢复到可见入口。
- 输入防抖/回车查询、取消请求及序号校验防止旧响应覆盖；刷新与错误保留已有结果、输入和滚动状态，失败可重试。

## 更新后启用

先按原方式备份数据库，正常停止并重新启动 `start_windows.bat`，浏览器 `Ctrl+F5` 强制刷新。不要同时运行新旧服务操作同一个库。原有成绩和旧批次不需要重新导入才能继续使用；只有需要补齐此前未保存的整行/易班 ID 时，才重新导入对应原报表。
