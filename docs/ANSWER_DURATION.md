# 答题时长功能与验收（2026-10-20）

## 使用

1. 建议先下载数据库备份，正常停止旧服务，再重新运行 `start_windows.bat`。
2. 浏览器按 `Ctrl+F5` 刷新，已有成绩可直接查看；没有时间的旧记录显示“—”，**不需要重新导入才能使用原成绩**。
3. 原来没有开始/结束时间列的报表可以照常导入，这两项始终选填。有完整时间时才按标准报表 **M列－L列**计算。
4. 只有想补齐时长时，才需上传含时间的报表、核对映射并确认。同分同状态且缺时长时可补齐，不为了补时长修改成绩。

旧程序没有保存的时间不能凭空恢复，但不影响成绩导入、显示和导出。更新不会自动读取用户本地文件或自动确认导入。

## 规则及显示范围

- **答题时长＝结束时间－开始时间，即M－L**，不用“系统评定时间”，也不以当前时间代替结束时间。
- 格式为 `时:分:秒`，例如 `00:12:53`；跨天照常相减，超过24小时不归零。真实0秒为 `00:00:00`，缺失页面显示“—”、导出留空。
- 开始/结束任一缺失或结束列为“未正常交卷”时，不计算时长；原标记在导入审计中保留，不自动改变分数或状态。“暂无”“未提供”“未填写”“未录入”“未结算”和隐藏空白也按缺失处理，而不是日期错误。非法日期、公式、时区不一致或负时长仍列为异常。
- CSV仅省略末尾可识别的可选时间单元格时也能正常导入，不强迫补空逗号；学号/分数缺列、中间错位或多余列仍须校验，不靠放宽身份绑定来消除报错。
- 前端兼容仅缺少时间功能的旧服务：正常导入成绩，不提交其不支持的时间映射，时间控件禁用并给出普通说明，不报时间功能错误。旧JSON记录/批次完全没有时间字段时也显示“—”。
- 支持完整日期时间文本及有明确日期格式的Excel日期单元格，兼容1900/1904日期系统；源时区未提供时不猜测UTC。原时间有小数秒时，计算结果不足1秒部分舍去。
- 成绩明细、导入清洗预览及历史、待跟进、异常人员及出现明细均展示时长；成绩编辑框只读显示原开始/结束及答题时长。名单导入和剔除预览展示当前在库时长。
- CSV、按班级/学院/勾选学生/全选筛选/不合格范围Excel、历史清洗明细、待跟进和异常导出均包含对应时间/时长；剔除核对CSV也同步。数据总览及Excel导出说明的人数统计不增加时长统计。
- 同分已有时间默认保持原来源，低分保护时保留高分的时间；新高分缺时间不沿用旧低分时长。同批最高分并列但完整时间不同则请求人工核对，不拼接不同答题记录。
- 时间随成绩提交、版本校验、审计和撤销一并保存/恢复。名单更新及手工修正分数不清空时间。启动时事务添加旧数据库的可空字段，不改既有分值；不要与旧版同时操作同一数据库。

主表在1440px桌面核验较长文本学号和完整时长不被右侧编辑列遮挡；窄屏使用表格自身横向滚动，不撑宽整页。自动分页按实际换行行高计算，保留已测边界行高度，避免末行遮挡或容量反复变化。

## 实现

- `server/exam_time.py`：时间解析、校验、时差及显示格式。
- `server/schema.sql`、`database.py`：三个可空字段及旧库增量升级，schema_version仍为2。
- `server/score_import.py`、`score_api.py`：可选时间映射、同分补齐、配套合并/审计/撤销。
- `server/app.py`、`score_export.py`、`follow_up.py`、`score_issues.py`、`roster_removal.py`：查询、预览及全部相关导出。
- `web/`：统一时长格式、成绩/预览/历史/核对表格与响应式布局。
- 当前能力版本：`exam_time_api_version=1`、`score_export_workbook_version=6`、`follow_up_api_version=4`。同时兼容不含时间的分班工作簿v5及跟进v3：照常查看、下载原格式，明确普通提示“不含答题时间”，不将旧文件冒充有时长的新文件。更老版本的及格规则/接口无法核对时仍保留原保护；本次只放宽缺少时间能力，不吞掉网络、身份、分数或并发错误。
